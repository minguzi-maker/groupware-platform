# 로컬 첫 실행

로컬에서 인프라, config-server, Eureka, user-service, API Gateway, tenant-web, ai-service를 띄우고, 화면에서 로그인·회원가입·소셜 로그인까지 확인하는 순서입니다. JDK 21, Docker, Python 설치는 [설치 가이드](../설치-가이드.md)를 따릅니다.

비밀 값(클라이언트 시크릿, Gmail 앱 비밀번호, Gemini API 키)은 채팅, 문서, Git에 적지 않습니다. 실행하는 창의 환경 변수로만 넣습니다.

명령은 명령 프롬프트(cmd) 기준입니다. 각 서비스는 저장소 루트에서 연 새 창에서 띄웁니다. `gradlew.bat`과 `npm`은 `call`로 실행합니다. 같은 줄을 배치 파일에 넣어도 다음 명령으로 돌아옵니다. `set`은 `=` 양쪽에 공백을 두지 않고, 값에 따옴표를 붙이지 않습니다. 창을 닫으면 값은 사라집니다. 이미 떠 있는 프로세스에는 적용되지 않으므로, 값을 바꾼 뒤에는 그 창에서 다시 띄웁니다.

서비스는 아래 순서로 설명합니다. 각 서비스에서는 데이터베이스, 환경 변수, 키 발급, 실행, 확인 순서로 적습니다.

| 순서 | 서비스 | 포트 |
|------|--------|------|
| 1 | config-server | 8888 |
| 2 | eureka-server | 8761 |
| 3 | user-service | 8082 |
| 4 | api-gateway | 8081 |
| 5 | `frontends/tenant-web` | 5173 |
| 6 | ai-service | 8100 |

## 인프라

저장소 루트에서 인프라를 띄웁니다. config-server는 RabbitMQ가 먼저 떠 있어야 하고, user-service는 PostgreSQL이 먼저 떠 있어야 합니다.
1. Docker Desktop을 실행하고 로그인합니다.
2. 터미널에서 `groupware-platform` 클론 폴더를 엽니다.
3. 인프라 컨테이너를 띄웁니다.

```bat
docker compose up -d
```

## 1. config-server

### 실행

config-server는 기동할 때 [groupware-platform-config](https://github.com/ibm05-team-3/groupware-platform-config)의 `dev` 브랜치를 받아 옵니다. 저장소를 받는 동안 잠시 걸립니다.

```bat
cd services\config-server
call gradlew.bat bootRun
```

### 확인

http://localhost:8888/actuator/health 가 `UP`이고, http://localhost:8888/user-service/dev 가 열리면 다음으로 넘어갑니다.

## 2. eureka-server

### 실행

```bat
cd services\eureka-server
call gradlew.bat bootRun
```

### 확인

http://localhost:8761 이 열리면 Eureka가 떠 있습니다. `USER-SERVICE` 등록은 user-service를 띄운 뒤에 확인합니다.

## 3. user-service

소셜 로그인 완료 주소는 게이트웨이(`8081`)로 고정되어 있습니다. 네이버·Google 키와 Gmail 앱 비밀번호는 config 저장소에 없습니다.

### 데이터베이스

`docker compose up`이 `user_service` 데이터베이스를 만듭니다. 테이블은 자동으로 채워지지 않으므로 `schema.sql`을 한 번 실행합니다. 이 파일은 없는 테이블만 만들고, 이미 있는 행은 지우지 않습니다.

명령 프롬프트에서 저장소 루트를 연 뒤 실행합니다.

```bat
docker exec -i groupware-postgres psql -U postgres -d user_service -v ON_ERROR_STOP=1 < services\user-service\src\main\resources\db\schema.sql
```

`schema-dev.sql`은 회원, 테넌트 테이블을 지우고 다시 만듭니다. 로컬 데이터를 비울 때만 씁니다.

`dev` 프로파일은 `application.yaml`에 이미 켜져 있습니다. 테이블이 있고 `admin@naver.com`이 없으면 기동할 때 그 계정을 한 번 넣습니다. 비밀번호는 `12341234`입니다.

### 환경 변수

user-service는 뜰 때 `http://localhost:8888`에서 설정을 읽습니다. `application-dev.yaml`의 Eureka 주소와 RabbitMQ 계정이 여기로 들어옵니다. 같은 키가 로컬 `application.yaml`에도 있으면 config-server 값이 우선합니다. 실행 창의 환경 변수는 그 설정보다 우선하고, 다른 서비스 창에는 넘어가지 않습니다.

명령 프롬프트에서는 `bootRun` 전에 같은 창에서 `set`으로 넣습니다.

```bat
set NAVER_CLIENT_ID=네이버 Client ID
set NAVER_CLIENT_SECRET=네이버 Client Secret
set GOOGLE_CLIENT_ID=구글 Client ID
set GOOGLE_CLIENT_SECRET=구글 Client Secret
set MAIL_ENABLED=true
set MAIL_USERNAME=보내는주소@gmail.com
set MAIL_APP_PASSWORD=Gmail 앱 비밀번호
set USER_WEB_URL=http://localhost:5173
```

| 변수 | 없을 때 | 설명 |
|------|---------|------|
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 기동 실패 | 네이버 로그인. 소셜을 쓰지 않아도 값이 있어야 뜹니다. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 기동 실패 | Google 로그인. 마찬가지입니다. |
| `MAIL_ENABLED` | `false` | `true`가 아니면 회원가입과 비밀번호 재설정이 거절됩니다. |
| `MAIL_USERNAME` | 비어 있음 | 보내는 Gmail 주소. `MAIL_ENABLED=true`이면 필수입니다. |
| `MAIL_APP_PASSWORD` | 비어 있음 | Gmail 앱 비밀번호. 계정 비밀번호가 아닙니다. |
| `USER_WEB_URL` | `http://localhost:5173` | 비밀번호 재설정 메일의 링크 앞부분. |

로그인 토큰 서명은 `application.yaml`의 로컬 기본 키를 씁니다. 게이트웨이의 공개 키와 이미 짝입니다. 한쪽만 바꾸면 로그인이 깨집니다.

### 키 발급

#### Google 로그인

콘솔: https://console.cloud.google.com/auth/clients

1. 프로젝트를 만들거나 고릅니다.
2. 처음이면 동의 화면을 만듭니다. 사용자 유형은 외부로 두고, 앱 이름과 본인 Gmail을 넣습니다.
3. 앱이 테스트 상태이면 테스트 사용자에 로그인할 Gmail을 추가합니다. 빠뜨리면 본인 계정으로도 로그인이 거절됩니다.
4. **Create client**에서 애플리케이션 유형을 **웹 애플리케이션**으로 고릅니다.
5. 승인된 JavaScript 원본에 `http://localhost:5173`을 넣습니다.
6. 승인된 리디렉션 URI에 아래를 그대로 넣습니다.

```text
http://localhost:8081/user-service/user/oauth2/code/google
```

7. 만든 뒤 보이는 Client ID와 Client Secret을 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 넣습니다. 시크릿 전체는 만들 때 한 번 보입니다.

요청 범위는 코드에 `openid`, `profile`, `email`로 들어 있습니다. 콘솔에서 범위를 더 열지 않아도 됩니다.

#### 네이버 로그인

등록: https://developers.naver.com/apps/#/register  
애플리케이션 설명: https://naver.github.io/naver-openapi-guide/appregister.html

1. 네이버 개발자 센터에 로그인하고 애플리케이션을 등록합니다.
2. 사용 API에서 **네이버 로그인**을 고릅니다.
3. 제공 정보는 **이름**, **이메일**만 고릅니다. 휴대전화는 고르지 않습니다. 코드도 그 둘만 요청합니다.
4. 서비스 환경은 PC 웹입니다.
5. 서비스 URL에는 `localhost`라는 이름을 넣을 수 없습니다. 아래를 넣습니다.

```text
http://127.0.0.1:5173
```

6. Callback URL은 코드의 `redirect-uri`와 글자까지 같아야 합니다.

```text
http://localhost:8081/user-service/user/oauth2/code/naver
```

7. 등록 후 보이는 Client ID와 Client Secret을 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 넣습니다.

Callback URL을 콘솔에서 다른 주소로만 바꾸면 로그인이 끝나지 않습니다. 바꿀 때는 `services/user-service/src/main/resources/application.yaml`의 `redirect-uri`도 같은 값으로 맞춥니다.

#### 회원가입 메일

회원가입 확인과 비밀번호 재설정은 Gmail로만 보냅니다. `MAIL_ENABLED`가 `false`이면 두 기능은 메일을 보내지 않고 실패합니다. 이미 만들어진 `admin@naver.com`으로 로그인하는 데는 메일이 필요 없습니다.

1. 보낼 Gmail 계정에서 2단계 인증을 켭니다. https://myaccount.google.com/signinoptions/two-step-verification
2. 앱 비밀번호를 만듭니다. https://myaccount.google.com/apppasswords
3. 화면에 나온 16자를 `MAIL_APP_PASSWORD`에 넣습니다. 공백은 빼도 됩니다. Gmail 로그인 비밀번호를 넣으면 발송이 거절됩니다.
4. `MAIL_USERNAME`에는 그 Gmail 주소 전체를 넣습니다. 보낸 사람 주소와 Gmail 로그인 주소가 같아야 합니다.
5. `MAIL_ENABLED`를 `true`로 둡니다.

앱 비밀번호 메뉴가 없으면 2단계 인증이 꺼져 있거나, 회사 Google 계정에서 관리자가 앱 비밀번호를 막아 둔 경우입니다.

메일의 재설정 링크는 `USER_WEB_URL`(기본 `http://localhost:5173`)로 시작합니다. 화면을 다른 포트로 열면 링크가 그 화면으로 가지 않습니다.

### 실행

IntelliJ에서는 이 값을 파일에 적지 않고, `UserApplication` 실행 설정의 Environment variables에만 넣습니다. 실행 설정을 Git에 커밋하지 않습니다. config-server가 설정을 주지 못하면 user-service는 기동을 멈춥니다.

```bat
cd services\user-service
set NAVER_CLIENT_ID=네이버 Client ID
set NAVER_CLIENT_SECRET=네이버 Client Secret
set GOOGLE_CLIENT_ID=구글 Client ID
set GOOGLE_CLIENT_SECRET=구글 Client Secret
set MAIL_ENABLED=true
set MAIL_USERNAME=보내는주소@gmail.com
set MAIL_APP_PASSWORD=Gmail 앱 비밀번호
set USER_WEB_URL=http://localhost:5173
call gradlew.bat bootRun
```

### 확인

1. http://localhost:8082/actuator/health 가 `UP`인지 봅니다. 데이터베이스가 맞지 않으면 `DOWN`입니다.
2. http://localhost:8761 에서 `USER-SERVICE`가 등록됐는지 봅니다.
3. 회원가입은 `MAIL_ENABLED=true`이고 Gmail 발송이 될 때 http://localhost:5173/signup 에서 확인합니다. 확인 코드는 입력한 Gmail로 갑니다. 화면은 tenant-web을 띄운 뒤에 열립니다.

## 4. api-gateway

### 실행

```bat
cd services\api-gateway
call gradlew.bat bootRun
```

### 확인

직접 호출할 때는 게이트웨이로 보냅니다.

```bat
curl.exe -i -X POST http://localhost:8081/user-service/user/login -H "Content-Type: application/json" -d "{\"email\":\"admin@naver.com\",\"password\":\"12341234\"}"
```

상태 `200`이고 본문에 `"authenticated":true`와 회원 번호가 있으면 됩니다. 응답에 `Set-Cookie`로 `session`이 붙습니다.

## 5. tenant-web

### 환경 변수

`.env`의 `VITE_BACKEND_API_BASE_URL`은 `http://localhost:8081`입니다.

### 실행

명령 프롬프트에서 `npm`은 `npm.cmd`로 실행됩니다.

```bat
cd frontends\tenant-web
call npm i
call npm run dev
```

Vite 기본 포트는 5173입니다. 다른 포트로 열리면 소셜 로그인 복귀와 재설정 링크가 어긋납니다.

### 확인

http://localhost:5173/login 에서 `admin@naver.com` / `12341234`로 로그인합니다.

## 6. ai-service

### 환경 변수

`GOOGLE_API_KEY`는 ai-service 창에만 넣습니다.

| 변수 | 없을 때 | 설명 |
|------|---------|------|
| `GOOGLE_API_KEY` | 비어 있음 | Gemini 호출에 씁니다. |

### 키 발급

발급: https://aistudio.google.com/apikey

1. Google 계정으로 로그인합니다.
2. 처음이면 이용 약관에 동의합니다. AI Studio가 기본 프로젝트와 키를 만듭니다.
3. 이미 Google Cloud 프로젝트가 있으면 Dashboard의 Projects에서 그 프로젝트를 가져온 뒤 키를 만듭니다.
4. **Create API key**로 키를 만들고 `GOOGLE_API_KEY`에 넣습니다. 2026년 5월 28일 이후 새 키는 승인 키입니다.

### 실행

가상환경이 없으면 먼저 만듭니다.

```bat
cd services\ai-service
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
```

```bat
cd services\ai-service
set GOOGLE_API_KEY=발급받은 키
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8100
```

### 확인

http://localhost:8100/health 응답이 `{"status":"ok"}`이면 ai-service가 떠 있습니다.
